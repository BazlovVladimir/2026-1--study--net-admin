   Порт коммутатора был активирован, что обеспечило корректное подключение устройства к сети.  
   В результате сформирована расширенная сеть с выделенным сервером DNS.

**Принцип работы DHCP:**  
DHCP автоматически назначает IP-адреса клиентам.  
Процесс включает четыре этапа:
- Discover — клиент отправляет широковещательный запрос  
- Offer — сервер предлагает IP-адрес  
- Request — клиент запрашивает предложенный адрес  
- Acknowledgment — сервер подтверждает выдачу адреса

## Исследование работы DHCP в режиме Simulation

8. Выполнен переход в режим **Simulation** для анализа процесса получения IP-адреса по протоколу DHCP.  
   В рабочей области отображены события передачи пакетов между устройствами, а также список событий, фиксирующий этапы обмена сообщениями.

   ![Передача DHCP-пакетов в режиме Simulation](Screenshot_9.png){ #fig:009 width=80% }

9. На первом этапе клиентское устройство формирует широковещательный запрос **DHCP Discover**.  
   В данном пакете:
   - IP-адрес отправителя: 0.0.0.0  
   - IP-адрес назначения: 255.255.255.255  
   - поле **Client Address** не заполнено  
   - используется MAC-адрес клиента для идентификации  

   Это сообщение рассылается всем устройствам сети с целью поиска DHCP-сервера.

   ![DHCP Discover (запрос клиента)](Screenshot_10.png){ #fig:010 width=80% }

10. После получения запроса DHCP-сервер формирует ответ **DHCP Offer**.  
    В данном сообщении сервер предлагает клиенту свободный IP-адрес.

    Основные параметры:
    - предложенный IP-адрес (поле **Your Client Address**)  
    - адрес DHCP-сервера  
    - параметры сети (маска, шлюз, DNS)  

    На данном этапе клиент ещё не использует адрес, а только получает предложение.

    ![DHCP Offer (предложение сервера)](Screenshot_11.png){ #fig:011 width=80% }

11. Далее клиент отправляет сообщение **DHCP Request**, подтверждая выбор предложенного IP-адреса.  
    Запрос также передаётся широковещательно, чтобы уведомить все DHCP-серверы о принятом решении.

    ![DHCP Request (подтверждение клиента)](Screenshot_12.png){ #fig:012 width=80% }

12. В завершение сервер отправляет сообщение **DHCP Acknowledgment (ACK)**, подтверждая закрепление IP-адреса за клиентом.  
    После этого клиент получает возможность использовать назначенные сетевые параметры.

    В ответе содержатся:
    - окончательно назначенный IP-адрес  
    - адрес шлюза  
    - адрес DNS-сервера (10.128.0.5)  
    - дополнительные параметры конфигурации  

    ![DHCP ACK (подтверждение сервера)](Screenshot_13.png){ #fig:013 width=80% }

13. В процессе анализа PDU установлено, что:
    - все начальные DHCP-сообщения передаются широковещательно  
    - идентификация клиента осуществляется по MAC-адресу  
    - в поле **Client Hardware Address** указывается уникальный MAC-адрес устройства  
    - сервер передаёт параметры сети через опции DHCP (например, DNS Server Option)

    **Последовательность работы DHCP (DORA):**
    - Discover — поиск DHCP-сервера  
    - Offer — предложение IP-адреса  
    - Request — запрос выбранного адреса  
    - Acknowledgment — подтверждение назначения  

# Контрольные вопросы

1. **За что отвечает протокол DHCP?**  

   **DHCP (Dynamic Host Configuration Protocol)** — это сетевой протокол, предназначенный для автоматической настройки сетевых параметров устройств в сети.  

   Он выполняет следующие функции:
   - автоматическая выдача IP-адресов клиентам;
   - назначение маски подсети;
   - указание шлюза по умолчанию;
   - передача адреса DNS-сервера и других параметров.

   Использование DHCP позволяет избежать ручной настройки каждого устройства, уменьшает вероятность ошибок и упрощает администрирование сети.

2. **Какие типы DHCP-сообщений передаются по сети?**  

   В процессе работы DHCP используется несколько типов сообщений, основными из которых являются:

   - **DHCP Discover** — широковещательный запрос клиента для поиска DHCP-сервера;
   - **DHCP Offer** — ответ сервера с предложением IP-адреса;
   - **DHCP Request** — запрос клиента на получение предложенного адреса;
   - **DHCP Acknowledgment (ACK)** — подтверждение сервера о выдаче адреса.

   Дополнительно могут использоваться:
   - **DHCP NAK** — отказ в выдаче адреса;
   - **DHCP Release** — освобождение адреса клиентом;
   - **DHCP Inform** — запрос дополнительных параметров без получения IP.

3. **Какие параметры могут быть переданы в сообщениях DHCP?**  

   В DHCP-сообщениях передаются различные параметры конфигурации сети:

   - IP-адрес клиента;
   - маска подсети;
   - адрес шлюза по умолчанию;
   - адрес DNS-сервера;
   - доменное имя;
   - время аренды IP-адреса (lease time);
   - адрес DHCP-сервера;
   - дополнительные опции (например, NTP-сервер, WINS и др.).

   Эти параметры передаются с использованием специальных полей и опций DHCP.

4. **Что такое DNS?**  

   **DNS (Domain Name System)** — это распределённая система доменных имён, предназначенная для преобразования символьных доменных имён в IP-адреса.  

   Благодаря DNS пользователи могут обращаться к ресурсам по удобным именам (например, www.example.com), а не по числовым IP-адресам.  

   DNS работает по принципу клиент-серверной модели: клиент отправляет запрос, а DNS-сервер возвращает соответствующий IP-адрес.

5. **Какие типы записи описания ресурсов есть в DNS и для чего они используются?**  

   В DNS используются различные типы ресурсных записей:

   - **A (Address Record)** — сопоставляет доменное имя с IPv4-адресом;
   - **AAAA** — сопоставляет доменное имя с IPv6-адресом;
   - **CNAME (Canonical Name)** — задаёт псевдоним для доменного имени;
   - **MX (Mail Exchange)** — указывает почтовые серверы домена;
   - **NS (Name Server)** — определяет DNS-серверы, обслуживающие домен;
   - **PTR (Pointer)** — используется для обратного разрешения IP-адреса в доменное имя;
   - **TXT** — хранит произвольную текстовую информацию (например, для SPF-записей).

   Эти записи позволяют организовать работу различных сетевых сервисов и обеспечить корректное разрешение имён в сети.

В режиме моделирования исследован процесс обмена сообщениями DHCP, включая этапы Discover, Offer, Request и Acknowledgment. Проанализирована структура DHCP-пакетов, а также особенности передачи широковещательных запросов и назначения параметров клиентским устройствам.

Дополнительно выполнена проверка сетевой связности между узлами из разных подсетей, что подтвердило корректную работу маршрутизации и сетевых сервисов. Полученные результаты позволили закрепить знания о принципах автоматической настройки сети и функционировании службы доменных имён, а также приобрести практические навыки администрирования сетевой инфраструктуры.
